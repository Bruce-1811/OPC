## 2. P0：交付与验收相关

### 2.1 云访问稳定性
- 确认安全组长期放行 **TCP 80**  
- 确认 PM2 startup + `pm2 save`，开机自启  
- MySQL、Nginx、opc-server、opc-ai 健康检查脚本化（可选一键 `status.sh`）  
- 准备固定测试账号（发布者 / 申请人）交给老师  

### 2.2 演示材料
- 按主链路录制演示视频（注册→发布→申请→审核→消息→问培风）  
- 本目录交付文档保持与代码同步更新

## 3. P0：问培风智能化（高价值）

当前：模型主要看到用户当轮问题；`suggestions` 多为空。

建议改造：

1. **Express 查询当前用户上下文**（任务待办、未读会话、待审申请）  
2. 拼成摘要，随请求传给 Python（system 或额外 user 消息）  
3. 按意图返回 `suggestions`（可跳转任务/消息/申请/发现）  
4. **多轮上下文**：把该用户最近 N 条 `ai_chats` 一并传给模型  
5. 模型失败时：Express 规则引擎降级（拼待办文案），减少前端离线 Mock 依赖  

验收标准示例：

- 问「今天要处理什么」→ 回复含真实待办或明确空态  
- 回复下方出现可点击建议并跳转正确页面

## 4. P1：产品功能增强

### 4.1 发布与草稿
- 发布页支持完整编辑标题、标签、角色、周期、截止日期  
- 「生成草稿」可对接 AI（当前多为本地整理预览）  
- 草稿列表与编辑路径持续回归测试  

### 4.2 项目执行
- 「已完成 / 已归档」状态流转接口与前端操作  
- 项目详情与项目 Tab 跳转、任务创建（不仅是勾选）  
- 待确认角标数量（申请数）实时显示  

### 4.3 消息
- 未读数角标准确性  
- 可选：简单推送或轮询优化  

### 4.4 匹配
- 发现页 `matchScore` / 技能匹配文案（若产品需要）

## 5. P2：工程与体验

| 项 | 说明 |
|----|------|
| 超时与重试 | Express 调 Python、Python 调大模型设置 timeout |
| 限流 | 按用户限制 AI 调用频率 |
| 日志 | 记录 AI 耗时、错误码（勿打密钥） |
| 流式输出 | 已有 SSE 能力，可评估是否经网关透传 |
| HTTPS | 若长期公网演示，可上证书 |
| 前端构建产物目录 | 建议固定放到 `/var/www/opc`，避免 `/root` 权限问题 |
| 目录名 | 历史拼写 `One-Person-Campany` 可择机纠正（成本较高） |
| UI | 对照 `opc介绍` 原型图系统打磨 |

## 6. 建议排期（参考 2～3 周）

| 周次 | 重点 |
|------|------|
| 第 1 周 | 公网稳定、演示视频、问培风上下文注入（P0） |
| 第 2 周 | suggestions + 发布编辑增强（P0/P1） |
| 第 3 周 | 项目状态流转、UI 与工程化（P1/P2） |

可按课程节点压缩：优先保证 **P0 全部可演示**。

## 7. 风险与依赖

| 风险 | 应对 |
|------|------|
| 大模型 Key / 额度 | 环境变量管理；准备降级文案 |
| 仅有 SSH 无控制台 | 安全组变更需账号所有者操作 |
| 双人并行冲突 | 继续按模块分文件；`routes/index` 小改先拉再推 |
| 数据被演示污染 | 定期清理测试数据或准备演示专用库 |
