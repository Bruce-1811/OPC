# OPC（One Person Company）

> **一人公司 · AI 原生的个人项目协作应用**  
> 帮助个人或小团队完成：**发现项目 → 发布招募 → 申请加入 → 协作执行 → 消息沟通 → AI 辅助**，面向移动端交互原型（Ant Design Mobile）。

本仓库是 **介绍资料 + 开发文档 + 可运行代码** 的 monorepo。队友 clone 后先看本文，再按角色进入对应文件夹：

- **要做功能 / 写代码** → [`opc开发/`](./opc开发/)（大纲、API、库表）
- **要先懂产品是什么、页面长什么样** → [`opc介绍/`](./opc介绍/)（概念报告、原型合集）

---

## 项目特色（给新成员 1 分钟版）

| 点 | 说明 |
|----|------|
| **产品定位** | 以「一个人也能发起/参与项目」为核心，不是传统企业管理软件，而是 **轻量 C2C 项目协作**。 |
| **AI 原生（规划）** | 发布页支持「想法 → AI 整理 → 再发布」（`POST /projects/ai-draft`，**暂未实现，阶段 2 预留**）；后续有「问培风」助手（阶段 6）。 |
| **移动优先** | UI 按手机原型设计，底部 5 Tab：**发现 / 项目 / 发布 / 消息 / 我的**。 |
| **契约驱动开发** | 后端约 33 个 MVP 接口、统一 `{ code, message, data }`；表结构见数据库设计文档，前后端按清单对齐。 |
| **可演示迭代** | 分 8 个阶段交付，每阶段结束都应能 demo，避免「全部做完再联调」。 |

**第一版 MVP 主链路（目标）：**  
发现 → 发布 → 申请 → 项目 Tab → 消息 → 我的 → 问培风 AI

### 阶段 2 已实现接口（后端 `opc-server`）

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/projects` | 创建项目或保存草稿 |
| GET | `/api/projects` | 发现页列表（关键词、分页） |
| GET | `/api/projects/drafts` | 我的草稿列表（需登录） |
| GET | `/api/projects/:id` | 项目详情（草稿仅发布者可见） |
| PUT | `/api/projects/:id` | 更新草稿 / 正式发布 |

认证与用户：`/api/auth/*`、`/api/users/me*`（见 API 清单）。

**刻意延后：** `POST /api/projects/ai-draft`、seed 脚本、详情「申请/私信」真实逻辑（阶段 3+）。

### 阶段 2 已实现页面（前端 `opc-web`）

| 路由 | 页面 |
|------|------|
| `/discover` | 发现：搜索 + 项目卡片 + 上拉加载 |
| `/publish`、`/publish/:projectId` | 发布 / 编辑草稿 |
| `/drafts` | 草稿箱（我的页也有入口） |
| `/projects/:id` | 详情：协作方式、角色、阶段、底部按钮（占位） |

### 2. 跑起来

```text

3. opc-server：npm install && npm run prisma:generate && npm run dev
4. opc-web：npm install && npm run dev
5. 浏览器打开 /api/health 与前端「发现」Tab
```

## 协作约定

- **分支：** 建议 `main` 稳定可 demo，`dev` 集成，功能用 `feature/阶段-简述`（团队自行统一即可）。  
- **秘密信息：** 勿提交 `opc-server/.env`；只提交 `.env.example`。  
- **API 响应：** 成功 `code: 0`；失败见清单中的业务码；列表分页 `data: { list, total, page, pageSize }`。  
- **鉴权：** 除注册、登录、公开项目列表/详情外，请求头 `Authorization: Bearer <token>`。
